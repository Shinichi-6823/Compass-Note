# コンパスヒヤリング

打合せのあとに、スマホでヒヤリング内容を入れてまとめる道具です。
**入力した内容は端末の中（localStorage）だけに保存します。外へは1バイトも送りません。**

欄はコンパス（案件管理 ＞ ヒアリング）と同じものを使っています。手で写していません ――
`tools/make-fields.mjs` がコンパスの `src/hearing.js` から `fields.js` を作ります。

---

## できること（2026-11-07 時点）

| | |
|---|---|
| ✅ 45欄の入力 | 7ステップ。片手で押せる縦長。★の優先度と色分けつき |
| ✅ 打合せメモ → 自動入力 | iPhone キーボードの 🎤 で話す → 「メモから項目を拾う」→ **候補を「使う」で入れる** |
| ✅ **納地は郵便番号から** | 7桁を数字キーで打って「住所を入れる」→ 都道府県・市区町村が入ります。「🗺 Googleマップで開く」で場所も確かめられます |
| ✅ **数・時間は打たせない** | 人数・物量・時間帯・寸法・日付の **16欄**は、数字キーと時計とカレンダーで入れます（かな変換が出ません） |
| ✅ 自動保存 | 手が止まって 0.4秒で保存。閉じるときもその場で保存 |
| ✅ 複数件の一覧・編集・削除 | 埋まり具合（n/45）つき |
| ✅ テキストコピー | メール・Teams に貼る形。空欄は出さない |
| ✅ PWA | ホーム画面に追加して、オフラインでも入力できる |
| ✅ **JSON（コンパス取り込み用）** | `_schema: "okamura-hearing/1"`。案件管理 ＞ ヒアリング ＞「JSONを読み込む」でそのまま読めます |
| ✅ **PDF** | ブラウザの印刷 → 「PDFに保存」。A4縦・1件1枚から |
| ✅ **CSV（台帳用）** | `Hearing.csv` と同じ列・同じ順。UTF-8 BOM つき。一覧から**まとめて1ファイル**にもできます |

**★「メモから項目を拾う」の決めごと**（コンパスの `loadsize.js` と同じ）

1. **当てずっぽうをしない** … 手がかりの語が同じ文に無ければ拾わない。読めない日付（「来年の春ごろ」）は返さない
2. **黙って入れ替えない** … 「使う」を押したときだけ欄に入る
3. **候補が2つあれば両方出す** … 選ぶのは人
4. **メモの全文は消さない** … 拾えなかった話が消えるのがいちばん困るため

## ★公開するまえに決めること

**GitHub Pages のサイトは、リポジトリを非公開にしても、インターネットに公開されます。**
閲覧者を制限できるのは GitHub Enterprise Cloud だけです。
つまり「リポジトリを private にすれば社内資料を隠せる」は **成り立ちません** ――
アプリが読む `fields.js` は、スマホに配られる以上、誰でも開けます。

そこで、**公開する版は 45欄だけで作ってあります**（`node tools/make-fields.mjs --45`）。

| | 中身 | 公開してよいか |
|---|---|---|
| **45欄（いまの版）** | 荷姿・SKU数・設置スペース・稼働予定・予算規模・コンペ有無… **物流の一般的な質問** | 判断しやすい |
| 129欄（全部入り） | ＋ 決裁者の趣味・意思決定方法・人脈・互恵・重視ポイント・提案予測… **営業の進め方そのもの** | 公開には向かない |

129欄の版は `node tools/make-fields.mjs`（引数なし）で作れます。
**社内（SharePoint・社内サーバなど https で配れる場所）に置くときだけ**にしてください。

> 45欄でも社外に出したくない、という判断もありえます。そのときは GitHub Pages をやめて、
> 社内の https のある置き場所に同じファイルを置けば、そのまま動きます（作りは何も変わりません）。

## iPhone での使い方

1. Safari で公開した URL を開く
2. 共有ボタン → **ホーム画面に追加**
3. ホーム画面のアイコンから開く（これで PWA として動き、オフラインでも入力できます）
4. 「＋ 新しく聞いた内容を入れる」→ **打合せメモでキーボードの 🎤 を押して話す**
5. 「メモから項目を拾う」→ 候補を確かめて「使う」
6. 次へ進みながら、拾えなかった欄を足す
7. 最後に「テキストをコピー」してメール・Teams へ

**`判定.html`** は、端末で何が使えるかを調べるページです（2026-11-07 に iPhone SE で実施ずみ）。

実機で分かったこと:

| | |
|---|---|
| 画面 | ホーム画面のアプリ **375×647** ／ Safari のタブ **375×549**。狭いほうに合わせて作ってあります |
| 音声認識（Web Speech API） | **使えません**（`aborted`）。だからキーボードの 🎤 を使う作りにしています |
| 録音・WebGPU・容量33GB | **使えます**。あとから端末内 Whisper を足す道は通っています |

## GitHub Pages への置き方

### ★この Mac では git が動きません

```
/usr/local/bin/git  … Intel 版のため動かない（Bad CPU type）
/usr/bin/git        … Xcode のライセンス未同意で止まる
```

`/usr/bin/git` を動かすには、ご自身で Terminal からこれを実行して同意が要ります（パスワードが要るので私には実行できません）。

```bash
sudo xcodebuild -license
```

同意したくない・面倒なときは、下の **B か C** が早いです。

### A. git を直してから（いちばん普通）

```bash
sudo xcodebuild -license
```

```bash
cd ~/Developer/コンパス/コンパスヒヤリング && git init && git add -A && git commit -m "コンパスヒヤリング 初版"
```

そのあと GitHub で空のリポジトリを作り、表示される `git remote add` 〜 `git push` をそのまま実行します。
最後に リポジトリの Settings ＞ Pages ＞ Source を **main / (root)** にすると公開されます。

### B. GitHub Desktop（CLI を使わない）

1. [GitHub Desktop](https://desktop.github.com/) を入れる
2. File ＞ Add Local Repository → `~/Developer/コンパス/コンパスヒヤリング` を選ぶ（「リポジトリではない」と出たら Create a repository）
3. Publish repository（**Keep this code private のチェックは好みで。どちらでもサイトは公開されます**）
4. GitHub の Settings ＞ Pages ＞ Source を main / (root)

### C. GitHub のウェブ画面にドラッグ＆ドロップ（★いまはこれ）

### ★ root には置きません（コンパスノートが居るため）

リポジトリの root には **コンパスノートの `index.html`** が置いてあります。
同じ名前のファイルをそこへ入れると**上書きして消してしまう**ので、
ヒヤリングは `hearing/` という**サブフォルダ**に入れます。

```
<リポジトリ>/
  index.html          ← コンパスノート（さわらない）
  …                   ← コンパスノートのファイル（さわらない）
  hearing/            ← ★ここをまるごと足す
    index.html  app.js  …  判定.html
```

| | |
|---|---|
| コンパスノート | `https://<あなた>.github.io/<リポジトリ名>/` |
| **コンパスヒヤリング** | `https://<あなた>.github.io/<リポジトリ名>/hearing/` |
| 判定ページ | `…/hearing/判定.html` |

**このアプリのファイルは中の道（`./app.js` のような書き方）しか使っていないので、
サブフォルダに入れてもそのまま動きます**（実際にサブフォルダで読ませて確かめました。
manifest の `start_url`・`scope`・アイコンも、ぜんぶ `hearing/` の中を指します）。

### 置き場所を分け合うことについて

GitHub Pages では、**同じリポジトリの2つのアプリが同じ置き場所（オリジン）を分け合います**。
サブフォルダに分けても、ブラウザから見ると預かり場所は共通です。そこで次のようにしてあります。

| | |
|---|---|
| **オフラインの預かり分** | 名前を `compass-hearing-…` にして、掃除のとき**その頭で始まるものだけ**を捨てます。★以前はオリジンの預かり分を**ぜんぶ**捨てる書き方になっていました。そのままだとコンパスノートのオフライン分を毎回消してしまいます |
| **受け持つ道** | `hearing/` の中だけ。root のコンパスノートの読み込みには口を出しません |
| **端末内のデータ** | `localStorage` の `ch1:idx` と `ch1:d:<番号>`。コンパスノートが同じ名前を使っていないか、一度だけ見ておいてください |

サーバーを止めた状態でサブフォルダから開き、**45欄ぜんぶが出ること・コンパスノートの預かり分が消えないこと**を確かめてあります。

### 手順

```bash
cd ~/Developer/コンパス/コンパスヒヤリング && node tools/make-public.mjs && open 公開用
```

一覧は手で書いていません。`index.html` と `sw.js` から読み取るので、**1つ忘れることがありません**
（実際に `export.js` を手書きの一覧から落としていました。画面が白くなります）。

1. GitHub で**そのリポジトリ**を開く（新しく作る必要はありません）
2. Add file ＞ Upload files
3. Finder の `公開用/` から、**フォルダ「hearing」を、中を開かずにそのままドラッグ**
   （フォルダごと落とすと `hearing/…` の形で入ります。中身だけを落とすと root に散らばるので注意）
4. Commit changes → 1〜2分で `…/hearing/` が開きます

**Pages の設定はさわりません。** すでに main / (root) で動いているので、サブフォルダは自動で公開されます。

**2回目からは、同じように `hearing` フォルダをドラッグすれば上書きされます。**

> 別の名前にしたいとき: `node tools/make-public.mjs <名前>`（半角英数字のみ。
> 日本語フォルダ名は URL が `%E3%83%92…` になり、Teams に貼ると読めない形になります）

### 上げ直したのに iPhone が古いまま、のとき

`sw.js` の`版`を上げてあるので、**ふつうは開き直すだけで新しくなります**（オフライン用の預かり分は自動で捨てられます）。
それでも古ければ、ホーム画面のアプリを一度消して、Safari で開き直して「ホーム画面に追加」し直してください。
入力したデータは端末の `localStorage` にあるので、アプリを消すと**一緒に消えます**。
大事な記録が入っているときは、先に書き出しておいてください。

**`.md` の文書（00〜02）と `tools/` `test/` は上げなくても動きます。**
`00_項目一覧と画面構成案.md` と `01_全項目一覧.md` には **129欄ぜんぶの名前が載っている**ので、
公開リポジトリには上げないほうがよいです。

## データの扱い

| | |
|---|---|
| 保存先 | `localStorage`（この端末の中だけ）。キーは `ch1:` で始まります |
| 送信 | **打ち込んだものは送りません。** 外へ出るのは次の2つだけで、どちらも**ボタンを押したときだけ**です |
| └ ① 郵便番号 | `zipcloud.ibsnet.co.jp` へ **7桁の数字だけ**（キー不要）。社名も住所もメモも送りません。コンパスの `detail.js` と同じ仕組みです。押さなければ何も出ません |
| └ ② 地図 | 「Googleマップで開く」で、**住所の欄の文字**を Google マップの検索に渡して**別の画面で開きます**。ページの中に地図は取り込みません（取り込むとAPIキーが要り、公開リポジトリに鍵を置くことになります） |
| 送らないもの | 社名・物件名・金額・打合せメモ・そのほか打ち込んだものは、どこへも出ません |
| 消えるとき | Safari の「履歴とWebサイトデータを消去」でサイトデータを消すと**消えます**。大事な内容は、その日のうちにテキストコピーで出してください |
| リポジトリ | 単価・顧客名・実データは入っていません |
